    Risks & defects (System map)

    Overview

    Customizer Core is the web app where sales reps, dealers and customers design team uniforms, build carts, get quotes and approvals, and place and track factory orders.

    Who uses it

    • Customer (end user): designs, saves, adds to cart, requests a quote. Cannot place orders directly.
    • Sales rep / dealer: places orders (card or terms), manages customers, sends items for coach approval, fixes On Hold items.
    • Managing rep, Product Pro, brand manager: rep-level access with extra permissions.
    • Coach approver: no login; reviews and approves items through an emailed token link.
    • Guest: can browse sports and designs; opening the builder asks for login.

    How it is built

    • Laravel back end, Inertia + Vue 3 front end, Pinia stores.
    • Prolook / QStrike API: system of record for accounts, saved designs and orders.
    • QX7 API: brand data: sports, styles, colors, product info, feature flags, roles.
    • Nexio card payments; Hybris order confirmation for some brands; S3 for images; a PDF service for spec sheets.
    • Many behaviors are switched by flags. See Feature flags.

    Login, accounts & roles

    Login checks the local password, then requires an activated account and a Prolook token, and re-syncs the role from QX7 every time. Sessions last 120 minutes.

    Login /login

    What users can do

    • Log in with email and password (page or modal). No "remember me".
    • Resend the activation link if the account isn't activated.
    • Log out to /, or to /login.

    Rules & validations

    • Not activated: logged out with "User is not yet activated" and a resend modal.
    • A Prolook token must be created; if Prolook refuses, the app grants brand access and retries, else "Something went wrong while generating access token".
    • Locked out after 5 failed attempts per email and IP.
    • Landing: GM1 rep who never updated their password → /update-password; rep with incomplete info → /users/profile; modal login → back to the same page; otherwise the intended page or / with "Welcome back {name}!".
    • Session: 120 minutes, no idle timeout in the browser. Logged-in users on guest pages go to /; guests on protected pages go to /login.
    • Forced logout: auth:logout-all logs everyone out on their next request, but only on routes with the can_logout_user middleware.

    Role sync and roles

    How the role is set at every login

    • QX7 can_place_order false → customer.
    • Otherwise by QX7 position: Customer → customer, Sales Rep → sales_rep, Owner → admin, Product Pro → product_pro, Brand Manager → brand_manager, other → customer.
    • Forced to sales_rep when the user belongs to a dealer of this brand, is a brand user, or has this brand assigned.
    • The session also stores the QX7 user type (dealer / brand_user / sales_rep).

    What each role reaches

    • All logged-in users: profile, address book (404 on brand 5), saved designs and logos, carts, orders.
    • Customers menu: Product Pro, sales rep, dealer, brand manager (menu only; no server check).
    • Users menu: Product Pro only (menu only).
    • Admin: team-store payout APIs.
    • Coach, player, family: team-store features.
    • Approver: no login; access by approval token.
    • Defined roles: customer, sales_rep, dealer, dealer_admin, product_pro, brand_manager, coach, player, family, admin.

    What users can do

      • Filters: General, Price (low→high, high→low, range slider), Gender, Sports, Type, Decoration, Category, Neckline, Sleeve, Hemline, Waistline, Fit Intent, Pant Cuff/Length, Cut.

    • Legacy sort: block pattern sort_order (blank = 99), then style sort_order; product lines by name.
    • Keyword search matches product name, style name, ship date, price item or brand item code. It ignores case and runs on every keystroke.
    • "NEW" while today is before tag_expiry_date. The General filter shows NEW styles only.
    • No results: "No Available Styles!".
    • Availability: for brand 69 or 3, only styles whose block_pattern_rule_id is in VITE_ALLOWED_UNIFORM are shown. VITE_EXCLUDED_STYLES hides styles in the new picker.

    • The new picker always loads page 1; paging is commented out.
    • The builder route requires login.

    • blockResetState keeps filter state when leaving the page. pl-mktg-site clears saved filters and is then removed from the URL.
    • isShareable=true + multiSelectedFilters restore a shared filter set (CRE-9561 workaround).

    3. Card payments go through Nexio, except emails listed in BYPASS_NEXIO_EMAILS.
    4. Send to Prolook POST /api/order/new: brand, rep (from the QX7 order-sending method, else the brand rep), PO, ID number, notes, shipping, billing ("c/o {organization}"), items, reorder items, add-ons.
    5. On success: discount usage is sent to QX7, the cart is completed, submitted_date is set, each PDF header gets customizer ID / IID / PO, parts become "submitted", and temporary ship dates sync. The order confirmation email goes out.
    6. On failure: the Nexio payment is voided, the database is rolled back and the API message is shown. There is no automatic retry.
